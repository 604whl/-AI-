# 生成正文功能 PRD

## 背景

当前产品已支持草稿分析、标题生成和一键优化稿，但报告页的「生成正文」仍处于 P1 占位状态。对于留学生求职机构、导师 IP 和运营团队，很多场景并不是改写已有长文，而是基于一个选题、标题或分析结论快速产出一篇可发布初稿。

生成正文应作为「分析后行动」的一环：用户完成分析后，可以基于内容类型、问题诊断、优化建议、人设和合规规则，一键生成符合小红书留学生求职赛道表达习惯的正文初稿。

## 目标用户

- 留学生求职机构运营：需要稳定产出获客型笔记正文，降低从选题到初稿的时间。
- 求职导师 / Career Coach：需要正文保持专业可信和个人 IP 口吻。
- 新人运营：需要按爆文结构生成可编辑初稿，学习 Hook、经历、结果和 CTA 的组织方式。

## 用户故事

- 作为机构运营，我希望在分析报告页点击「生成正文」，自动得到一篇五段式正文，以便把诊断建议快速转成可发布草稿。
- 作为导师 IP，我希望生成正文能按导师语气、案例可信度和软 CTA 输出，以便不破坏个人专业人设。
- 作为新人运营，我希望生成结果标注段落结构和 CTA，以便知道每段承担什么运营目标。
- 作为内容审核者，我希望生成正文自带合规提示，以便避免「保证 offer」「100% 上岸」等高风险承诺。

## 范围

### P1 必做

- 在分析报告页启用「生成正文」按钮。
- 支持基于已完成分析任务生成正文：`POST /analysis/{id}/body`。
- 输出五段式结构：Hook、问题放大、真实经历、结果展示、CTA。
- 支持人设继承：`agency`、`mentor`、`senior`。
- 支持生成目标：高点击、高收藏、高转化、焦虑型、Offer 型、信息差型。
- 支持正文长度控制：默认 900 字，可选 500-1500 字。
- 生成结果可编辑、复制、重新生成。
- 输出合规提示，命中风险词时不阻断展示，但需提示修改建议。

### P1 可选

- 支持独立正文生成：`POST /body`，输入标题、选题摘要、目标和人设。
- 支持关键词强制包含，最多 5 个。
- 支持语气微调：默认、更焦虑、更专业、更亲和。

### 前端状态

- Loading：按钮进入加载态，抽屉展示生成中骨架屏和预计等待文案。
- Success：抽屉展示正文、结构大纲、CTA、合规提示、复制和重新生成按钮。
- Empty：分析任务缺少标题和正文上下文时，按钮禁用并提示先补充内容。
- Error：模型失败或解析失败时展示错误提示和重试入口。

## 非目标

- 不自动发布到小红书。
- 不生成封面图片。
- 不承诺真实数据结果或就业结果。
- 不做长篇文章、多平台改写或团队协作审批流。
- 不替代「优化稿」功能；优化稿偏改写已有草稿，生成正文偏从分析/标题产出新初稿。

## 验收标准

| 验收项 | 标准 |
|--------|------|
| 入口 | 报告页任务状态为 `completed` 时「生成正文」可点击；其他状态禁用 |
| 请求 | `POST /analysis/{id}/body` 至少携带 `goal`，可携带 `tone`、`maxLength`、`keywords` |
| 输出结构 | 返回 `body`、`structureOutline`、`cta`、`complianceWarnings`、`promptVersion`、`wordCount` |
| 五段式 | `structureOutline` 固定 5 项，顺序为 Hook、问题放大、真实经历、结果展示、CTA |
| 垂类相关性 | 正文至少包含 1 个留学生求职相关元素，如留学生、海归、秋招、面试、offer、简历、内推等 |
| 人设一致性 | `agency` 偏机构服务 CTA，`mentor` 偏专业建议 CTA，`senior` 偏经验分享 CTA |
| 合规 | 不默认输出「保证 offer」「100% 上岸」「包进大厂」等绝对化承诺；如模型返回命中，必须进入 `complianceWarnings` |
| 字数 | `wordCount` 不超过请求 `maxLength` 的 115%；低于 500 字时前端提示内容偏短 |
| 性能 | P95 < 30 秒；超时返回 `50403 body_generation_timeout` |
| 失败兜底 | AI 返回非 JSON 或缺字段时自动重试 1 次；仍失败返回 `50003 ai_response_invalid` |

## 接口 / 数据影响

### 新增接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/analysis/{id}/body` | 基于分析任务生成正文 |
| POST | `/body` | 独立正文生成，可选 |

### 请求字段

- `analysisId`：从路径取得，后端校验任务归属和完成状态。
- `goal`：生成目标，枚举与标题生成保持一致。
- `tone`：语气，默认 `default`。
- `maxLength`：正文长度上限，500-1500，默认 900。
- `keywords`：可选关键词，最多 5 个。
- `title` / `brief`：独立生成时使用，二者至少一项。

### 响应字段

- `analysisId`：关联分析 ID，独立生成时为 `null`。
- `goal`：生成目标。
- `body`：可编辑正文。
- `structureOutline`：五段结构摘要。
- `cta`：正文末尾转化引导。
- `complianceWarnings`：合规风险提示。
- `promptVersion`：正文生成 Prompt 版本。
- `wordCount`：正文估算字数。

### 配额与埋点

- 新增配额动作：`body_generation`。
- 免费用户建议每日 3 次，付费用户按订阅规则放开。
- 埋点：点击生成、生成成功、生成失败、复制正文、重新生成、编辑后复制。

## 风险与依赖

- 依赖分析报告质量；如果分析类型或建议偏差，正文生成会放大偏差。
- 依赖合规规则兜底；AI 可能生成夸大承诺，需要后处理扫描。
- 需要与优化稿功能区分清楚，避免用户不知道该点哪个按钮。
- 生成正文可能带来更高模型成本，需要配额控制和超时策略。

## 优先级

P1。建议在「优化稿」稳定后上线，作为报告页行动区第三个可用能力；独立正文生成 `/body` 可后置。
